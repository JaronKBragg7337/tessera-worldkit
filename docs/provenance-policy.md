# Provenance policy

SPDX-License-Identifier: CC0-1.0

## The promise

Everything in this repository may be used, copied, modified, redistributed, sold
and built upon, immediately, with no attribution. Code is `0BSD`; assets,
schemas and documentation are `CC0-1.0`.

## Why it is safe

Because nothing external was ever read.

Every mesh here is produced by a Python function in `kits/shell_v1/parts.py`
using only the geometry kernel in `src/tessera/`. No mesh, texture, model,
photograph, scan, capture or asset library is opened at any point in the
generation pipeline. `provenance.source_inputs` is empty for every asset, and
the validator **fails** any asset for which it is not.

That is a stronger position than "we used CC0 sources". CC0 solves permission;
it does not solve verification. A downloaded asset requires you to trust the
uploader's own rights, and a chain of trust you cannot inspect is not one you
can pass on to someone building a paid product on top of your work.

## The rules

**1. Three acceptable origins, and nothing else.**

- created originally for this project by a script in this repository
- created originally for this project by a person with full rights
- already owned outright, with rights sufficient for `CC0-1.0` redistribution

**2. Anything uncertain is quarantined, not included.** Not "included with a
note". Not "included pending review". Excluded, until the question is answered.

**3. Third-party *tools* may be used; third-party *content* may not.** Blender,
Trimesh and pytest are used to build, verify and test. None of them contributes
geometry, and none of them imposes conditions on generated output. A tool whose
licence attached conditions to its output would be replaced, not accepted.

**4. No protected designs.** No copies or near-copies of identifiable
characters, branded designs, distinctive fictional creations, proprietary game
assets or recognisable third-party artwork — regardless of how the geometry was
produced. Generating something from scratch does not make a recognisable
knock-off acceptable.

**5. Provenance is per asset, and it is enforced.** `TSR_ASSET_MISSING_PROVENANCE`
fails an asset with an incomplete record. `TSR_ASSET_UNREVIEWED_THIRD_PARTY`
fails an asset marked `third-party` without a completed licence review. These
run on every build.

## What is recorded

`provenance/manifest.json`, regenerated by `tools/provenance.py`:

- for every asset: origin, the exact generating function and its version, the
  author, source inputs (empty), third-party review status, the geometry hash,
  the licence, and a SHA-256 plus byte count for every generated file
- for every generator: path and SHA-256, so the code that produced the assets is
  itself pinned
- the third-party dependency list, split by whether it affects output — all
  three current entries are test-only and affect nothing
- the conceptual lineage from the two predecessor repositories: what was carried
  forward, what was rejected, and the explicit statement that no code was copied

## On the predecessor repositories

Tessera was designed after inspecting two earlier repositories of mine. Both are
mine, both remain intact, and neither was merged into this one.

`asset-pack-ue-threejs-blender-unity` is `CC0-1.0` and
`World-Printer-Lab-For-3D-Worlds` is `MIT`. **No code was copied from either.**
Concepts were carried forward and reimplemented against a new contract — the
single-source-of-truth config with a refusing `validate()`, script-only
generation, world-space texel density, connectors as position-plus-normal-plus-
kind, opposed-normal mating, and scale classes as standards. The MIT-licensed
repository's *ideas* are not subject to MIT's notice requirement; its *code*
would be, which is why none of it is here.

That distinction is recorded in `provenance/manifest.json` under
`conceptual_lineage`, with `"code_copied": "none"` per source, so the claim is
auditable rather than merely stated.

## If you contribute

You warrant that you have the right to release your contribution under `0BSD`
and `CC0-1.0`, and that it contains no third-party material. See
[`CONTRIBUTING.md`](../CONTRIBUTING.md). Contributions that add binary assets
not generated by scripts in this repository will be declined — not because the
assets are suspect, but because accepting one turns an auditable claim into an
unverifiable one.
